# GestaltX Canvas Lab 0.1 — iPhone 13 / iOS 27.2 실험용 소스 패치

작성·최종 패키징: 2026-11-14

**전달 상태: 소스 ZIP 완성 / 호스트 테스트 24개 통과 / IPA 미빌드 / 실기기 미검증.**
이전에 받은 README만이 아니라, 이번 ZIP에는 아래 설명에 해당하는 실제 추가 소스와 빌드 구성이 들어 있습니다.

## 무엇을 받았나요?

이 ZIP은 **완성 IPA가 아니라**, GestaltX 1.1.1에 캔버스 해상도 실험 기능을 추가하는 소스 패치와 GitHub Actions 빌드 구성입니다. GitHub에서 빌드에 성공하면 별도의 IPA 아티팩트가 만들어집니다. 여기서는 Xcode 빌드, 서명 후 설치, 실기기 접근 권한, 해상도 반영, 통화 표시 개선을 검증하지 않았습니다. 동작 보장 또는 복구 보장은 없습니다.

‘버튼만 있는 진단기’는 아닙니다. 접근이 허용되면 실제 기존 설정 파일을 백업하고 두 키를 수정하는 경로가 포함되어 있습니다. 다만 현재 공개된 worse_query의 지원 경로에 해당 Preferences 경로가 명시되어 있지 않으므로 **접근 거부로 종료될 가능성이 있습니다.** 이전 iOS에서 Nugget으로 성공했다는 사실이 현재 접근 권한까지 보장하지는 않습니다.

## 적용 대상 및 범위

- 물리 기기: **iPhone 13 (`iPhone14,5`)만**
- OS: **iOS 27.2.0만**. 27.2.1 등도 이 실험에서는 차단합니다.
- 원본 소스: GestaltX v1.1.1
- 고정 커밋: `f34d5a7271c14e540edb58e328dc9c06f8f3368f`
- 대상 파일: `/var/mobile/Library/Preferences/com.apple.iokit.IOMobileGraphicsFamily.plist`
- 별칭: `/private/var/mobile/Library/Preferences/...`도 같은 방식으로 시도
- 수정 키: 정수형 `canvas_width`, `canvas_height`
- 프리셋: **1206 × 2622**, **1179 × 2556**. 앱에는 각각 18 Pro/14 Pro 레이아웃 대응 실험으로 표시하지만, 이는 시험할 후보 값이지 해당 레이아웃과의 적합성 또는 겹침 해소가 검증된 값이 아닙니다.
- MobileGestalt의 다른 키, 모델/보드/CPU 식별값, 통화 표시 기능 플래그는 이 추가 화면에서 변경하지 않습니다.
- 없는 대상 plist나 Managed Preferences 설정을 새로 만들지 않습니다.
- 임의 경로 입력, 원격 제어, 자동 재시작, 구형 부분 복원 수단을 포함하지 않습니다.

위 해상도는 목표 캔버스 값입니다. 아이폰 13의 물리 패널을 다른 해상도로 바꾸거나 노치 하드웨어를 없애는 것이 아닙니다. 두 통화 표시가 겹치는 원인이 캔버스 외의 플래그/상태 표시줄 구성에도 있다면 해상도 적용 후에도 증상이 남을 수 있습니다.

## 먼저 알아야 할 위험

**중요: 전체 기기 백업 없이 적용하지 마세요.** 이 실험은 화면 이상, 터치 위치 불일치, 재시작 후 조작 불능, 설정 덮어쓰기 또는 복원 실패를 유발할 수 있습니다. 이때 앱을 열 수 없다면 내장 ‘원본 복원’ 버튼도 사용할 수 없습니다. 전체 기기 복원이 필요할 수 있으며, 기기나 OS 상태에 따라 현재 OS 버전을 유지하지 못할 수 있습니다.

내장 백업은 전체 기기 백업을 대체하지 않습니다. 전체 기기 백업과 별도로, 현재 GestaltX에서 **MobileGestalt 원본/현재 백업도 앱 밖으로 내보내세요.** 서명 정보·번들 ID가 달라지거나 앱을 삭제하면 앱 데이터/복원 키에 접근하지 못할 수 있습니다. 실험 적용 후에는 앱을 삭제하거나 재서명 방식을 바꾸지 마세요.

## 가장 쉬운 빌드 방법 — GitHub 웹 화면

맥이 없어도 GitHub의 macOS 실행 환경에서 빌드를 시도할 수 있습니다. Xcode/IPA 컴파일은 이 단계에서 처음 실제로 검증됩니다.

1. ZIP을 압축 해제합니다.
2. 자신의 GitHub 계정에 빈 저장소를 하나 만듭니다. README를 추가해 기본 브랜치를 만들어 두어도 됩니다.
3. **Add file → Upload files**에서 이 ZIP 안의 **내용물**을 저장소 루트에 업로드합니다. `apply_patch.py`와 `overlay/` 폴더가 루트 바로 아래에 있어야 합니다. 바깥쪽 폴더 하나로 감싸서 올리지 마세요. 테스트/설명 파일도 함께 올려도 됩니다.
4. ZIP에는 `.github/workflows/canvas-lab.yml`도 들어 있습니다. 업로드 뒤 이 파일이 저장소에 보이는지 확인합니다. 숨김 폴더라 빠졌다면 **Add file → Create new file**에서 파일명 `.github/workflows/canvas-lab.yml`을 입력하고, 루트의 `BUILD_WORKFLOW.yml` 내용을 그대로 복사해 저장합니다. 둘은 같은 내용입니다.
5. **Actions → Build GestaltX Canvas Lab (experimental) → Run workflow**를 실행합니다. 필요하면 자신의 저장소에서 Actions를 먼저 활성화합니다. 구성은 먼저 `host-tests`를 실행하고, 통과하면 macOS의 `build` 작업을 시작합니다.
6. 실행이 성공하면 해당 실행 화면 하단의 **Artifacts → GestaltX-CanvasLab-IPA-UNTESTED**를 다운로드합니다. 내려받은 ZIP 안에 `GestaltX_CanvasLab_1.1.1.ipa`가 있습니다.
7. `GestaltX-CanvasLab-source`에는 그 실행에 사용된 수정 소스도 포함됩니다. IPA를 다른 사람에게 재배포한다면 해당 소스와 원본 라이선스도 함께 제공하세요.

**실행이 빨간색으로 실패했다면 IPA가 완성된 것이 아닙니다.** 실패 단계의 오류를 확인해야 합니다. 구성은 `macos-latest`에 Xcode 27 이상이 있는지 확인하고, 없으면 `Require Xcode 27 or newer` 단계에서 중단합니다. 원본 저장소의 `xcode-27` 실행 환경을 사용자의 저장소에서도 쓸 수 있다고 가정하지 않았습니다. 필요한 Xcode가 없다면 본인 Mac의 Xcode 빌드 또는 해당 버전을 갖춘 실행 환경이 필요합니다. Rust/iOS 의존성 설치나 Swift/Objective-C 컴파일에서도 실패할 수 있습니다. 이 구성은 현재 채팅에서 실제로 실행한 CI 결과가 아닙니다. Actions나 의존성의 향후 변경도 영향을 줄 수 있습니다.

Apple 인증서, Apple ID 비밀번호 또는 GitHub 개인 액세스 토큰을 소스/워크플로에 넣지 마세요. 빌드 산출물은 ad-hoc 서명으로 패키징되며, 실제 설치 전 재서명이 필요합니다.

## 아이폰에 설치하고 실험하는 순서

1. 전체 기기 백업과 GestaltX의 MG 백업을 따로 보관합니다.
2. 기존 GestaltX에서 정상 작동했던 서명/설치 방법을 사용합니다. AltStore/SideStore 등을 통해 **앱과 내장 공유 확장에 공통 App Group을 유지**해야 합니다. 원본 GestaltX와 같은 제약입니다. 확장을 제거하거나 App Group이 없는 서명으로 바꾸지 마세요.
3. 현재 설치본과 번들 ID가 같으면 업데이트/덮어쓰기로 설치될 수 있습니다. 설치 전 내보낸 백업을 반드시 확인하고, 적용 후 삭제·재설치에 의존하지 마세요.
4. 설정 → 디스플레이 및 밝기 → 디스플레이 확대에서 **표준**으로 되돌립니다. 변경을 완료한 뒤 앱을 엽니다.
5. 앱은 `Canvas Lab · 실험판` 화면으로 시작합니다. 자동으로 시스템 설정을 쓰지 않습니다. 필요하면 ‘원래 GestaltX 화면 열기’에서 기존 18 Pro 레이아웃이 설정되어 있는지 확인한 뒤 실험 화면으로 돌아옵니다.
6. **설정 변경 없이 접근 검사**를 누릅니다.
   - 접근 거부/파일 검증 실패: 설정을 바꾸지 않고 중단됩니다. ‘진단 로그 내보내기’로 결과를 보관합니다.
   - 검사 통과: 기존 파일을 읽고 `O_RDWR`로 열 수 있었다는 뜻입니다. 실제 원자적 교체 권한 또는 화면 효과를 입증한 것은 아닙니다.
7. 현재 18 Pro 레이아웃이라면 **1206 × 2622**를 선택합니다. 백업·표준 배율·위험 확인 항목을 체크하고 ‘실험 적용’을 누른 뒤 확인 창에서 다시 적용을 선택합니다.
8. 최초 적용은 원본 바이트를 백업하고 인증/저장/재읽기 확인을 한 뒤 진행합니다. 이후 두 키를 바꾸고, 같은 디렉터리의 임시 파일 검증 후 원자적 이름 교체를 시도합니다. 직접 원본 파일을 `O_TRUNC`로 비우지 않습니다.
9. **파일 재확인 성공**으로 표시되면 백업과 로그를 앱 밖으로 내보냅니다. 그 후 직접 기기를 완전히 재시작합니다. 이 앱은 자동 재시작하지 않습니다.
10. 새로 찍은 스크린샷의 실제 픽셀 크기와 통화 중 시계/초록색 표시/Dynamic Island의 중복 여부를 확인합니다. 화면에 안 보인다고 즉시 다른 해상도를 연속 적용하지 마세요.
11. 개선되지 않으면 ‘실험 전 원본으로 복원’을 실행하고 결과를 확인한 뒤 필요하면 재시작합니다. 14 Pro 프리셋은 원래 GestaltX의 레이아웃도 해당 프리셋으로 맞춘 별도 실험일 때만 선택하세요.

## 실패 시 결과 해석

- `ACCESS_DENIED_OR_UNSUPPORTED_FILE`: 이 실행에서는 대상 파일을 안전하게 열 수 없었습니다. 설정 파일을 새로 만들거나 권한 검사를 우회하지 않았습니다.
- `Directory extension`/`File extension` 음수: worse_query 접근 요청 실패입니다. 정확한 원인은 원본 GestaltX 로그도 함께 보아야 합니다. 추가 화면의 반환값만으로 어떤 보안 계층이 거부했는지 확정할 수 없습니다.
- 검사 통과 후 임시 파일 생성/메타데이터 복사 실패: 파일 자체 열기와 디렉터리의 교체 권한은 다를 수 있습니다. 커밋 전 실패하면 원본은 교체하지 않습니다.
- `REPLACED_AND_VERIFIED`: 디스크의 파일 바이트를 수정하고 재읽기로 확인했다는 뜻입니다. iOS가 그 값을 사용하거나 UI 문제가 해결됐다는 뜻은 아닙니다.
- `directory fsync not confirmed`: 파일 재읽기는 일치했지만 디렉터리 항목의 동기화를 확인하지 못했습니다. 갑작스러운 전원 차단 상황의 지속성을 보장하지 않습니다.
- 파일 교체 후 재검증 실패: 파일은 바뀌었을 수 있습니다. 즉시 재부팅하지 말고 로그와 백업을 보관하세요. 덮어쓰기 경쟁 가능성 때문에 맹목적 자동 복원은 하지 않습니다.
- 복원이 ‘현재 파일이 기록과 다름’으로 차단됨: iOS나 다른 프로그램이 이 파일을 바꿨을 수 있습니다. 무관한 변경까지 덮어쓰지 않으려고 중단한 것입니다. 강제 덮어쓰기 버튼은 없습니다.

구형 Nugget/BookRestore/SparseRestore 절차로 우회하지 마세요. 이 패치는 해당 방법을 호출하지 않습니다.

## 백업과 복원 한계

- `Documents/CanvasLab/original-backup.plist`는 **첫 실험 직전의 파일**입니다. 공장 기본값을 추측해 만든 백업이 아닙니다.
- 첫 백업을 이후 적용 때 덮어쓰지 않습니다. 백업/상태 파일은 동기화 및 재읽기를 확인하고 디렉터리 동기화는 가능한 범위에서 시도합니다. 갑작스러운 전원 차단에 대한 완전한 지속성 보장은 아닙니다.
- 백업/상태 기록은 기기 전용 Keychain 키로 인증합니다. 키는 ZIP/로그/내보낸 백업 안에 포함하지 않습니다.
- 같은 기기에서 Keychain 키에 접근할 수 있고 모델/OS 빌드가 일치해야 복원할 수 있습니다.
- 원본 및 이 실험이 기록한 파일 상태와 다른 현재 파일은 자동 덮어쓰지 않습니다. OS가 재시작 시 설정을 다시 쓴 경우에도 복원이 차단될 수 있습니다.
- 검사 자체는 디스플레이 설정 바이트를 변경하지 않지만, worse_query의 App Group 접근 과정은 원본 GestaltX 구현에 따라 임시 Caches 링크를 만들고 복구합니다. 장치 전체에 ‘어떤 쓰기도 없는’ 검사는 아닙니다.
- 파일 교체 전후 검사로 위험을 줄였지만, 시스템 데몬은 이 앱의 파일 잠금을 따를 의무가 없습니다. 모든 경쟁 조건이나 전원 차단을 막는다고 보장하지 않습니다.

## 검증한 것 / 검증하지 못한 것

최종 소스 수정 후 합성 plist/소스 픽스처로 다시 수행한 **호스트 테스트 24개는 통과**했습니다. `host-test-results.txt` 참조. 이는 실제 iOS 파일이나 화면에서 수행한 테스트가 아닙니다.

검증한 것:
- 이 키트의 C 파일 교체 루틴이 합성 파일을 교체하고 바이트를 재확인하는지
- 무관한 plist 값 보존, 원본 바이트 복원, 기본 파일 모드 보존
- 스냅샷 불일치, inode 교체, 심볼릭/하드 링크, 그룹 쓰기 허용 파일, 빈/과대 입력, 대상 파일 없음의 거부
- 임시 파일 이름 충돌 시 기존 파일을 덮어쓰지 않는지 및 모든 임시 이름이 점유됐을 때의 중단
- 특수 권한, 경쟁 잠금, 열린 뒤 내용 변경, null 입력, 디렉터리가 아닌 핸들의 거부
- 소스 패치 적용/재실행/드라이런, 끝 개행 허용, 예상과 다른 시작 파일·심볼릭 링크·부분 패치의 거부

검증하지 못한 것:
- Xcode/Swift/Objective-C 컴파일과 GitHub Actions 실행
- Apple 전용 `fcopyfile` ACL·확장 속성, 파일 플래그 및 파일 보호 클래스 처리(해당 기능이 SDK에 노출될 때)
- App Group 재서명, 실제 worse_query 권한, 실기기 파일의 스키마/소유자/접근성
- iOS 27.2에서 canvas 키 사용 여부, 재시작 후 지속성
- 노치와 통화/Dynamic Island 표시 중복 해소 및 조작 불능 시 복구

테스트 수는 실기기 안정성 또는 보안 검증 수치가 아닙니다.

## 파일 구성

- `overlay/`: 추가할 SwiftUI 화면, Objective-C 백엔드, C 파일 교체 루틴
- `apply_patch.py`: 고정 버전 시작 파일을 검사하고 원래 소스를 보관한 뒤 추가 화면 연결
- `BUILD_WORKFLOW.yml`: 사용자가 자신의 저장소에 등록할 IPA 빌드 구성
- `tests/test_host.py`: 합성 파일/소스용 테스트
- `host-test-results.txt`: 작성 중 실행한 호스트 테스트 결과
- `NOTICE.md`, `LICENSE`: 출처, 비공식 수정 안내, GPLv3 전문
- `.github/workflows/canvas-lab.yml`: 등록 가능한 빌드 구성(루트 `BUILD_WORKFLOW.yml`과 동일)
- `MANIFEST.sha256`: ZIP 내 파일들의 SHA-256 목록

## 직접 Xcode로 빌드하는 경우

본인의 Mac에 Xcode 27 및 원본 프로젝트의 빌드 의존성이 필요합니다. 검토한 고정 커밋을 준비한 다음:

```sh
python3 /path/to/canvas_lab_kit/apply_patch.py /path/to/GestaltX
```

이 명령은 소스만 바꾸며 IPA를 생성하지 않습니다. 원본 저장소의 Native/DeviceConsole 빌드 과정과 `.github/scripts/build-ipa.sh`를 따라야 합니다. 앱과 공유 확장의 공통 App Group을 유지하세요.
